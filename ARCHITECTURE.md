# Kogen Rust architecture

Status: implementation plan and compiling skeleton, not a conformance claim. Authority order is `../kogen-spec/CLI-RULE.txt` (including its 6 October Grok name addendum), `../kogen-spec/spec/`, `../kogen-spec/quint/{CLASSIFICATION,REVIEW,ADAPTER,PLAN-NEXT}.md`, then the versioned black-box suite on `../kogen-conformance` branch `v1.2`. `../careful-rebuild` is reference material only. The public command and option grammar is frozen; `kogen-xspec` is a separate private executable.

## Workspace and boundaries

| Crate / module | Responsibility |
|---|---|
| `kogen` binary | Fresh-process argument grammar, embedded byte-exact help corpus, stdout/stderr and exit mapping, signal handling. No state policy. |
| `kogen-core::project`, `intent` | Project/origin/base resolution; strict YAML subset; Intent byte-preserving parser, lint, acceptance source location. |
| `kogen-core::approval`, `git` | SHA-256 of `intent.md || 0x00 || acceptance source`; late re-read; protected manifest; immutable approval commit and Git ref CAS. |
| `kogen-core::queue`, `status`, `recovery` | Origin-wide serial claim, priority/time/slug drain, stop/duplicate start, status precedence, dead-owner and post-CAS reconciliation. |
| `kogen-core::run`, `gate` | Durable journal, child process custody, workspace construction, acceptance ledger and baseline-relative checks, candidate protection, verified landing. |
| `kogen-core::provider` (split into `chatgpt`, `grok`, `auth`, `http`, `sse`, `session`, `tools`) | Owned login and credentials, request construction, streaming, retries, tool dispatch, stable Build cache affinity and usage. No external agent CLI. |
| `kogen-xspec` binary | Private `xspec/1` JSONL decoder/effect injector/observation mapper. Calls `kogen-core` production transitions, never implements a second state machine. |

Keep policy as pure `step(state, event) -> (state, effects)` functions where possible. Production interprets effects through narrow Git, filesystem, clock, process and HTTP ports. Replay injects observed effect results into those same functions. An effectful trace uses actual hashing or a temporary Git origin when an injected result would hide the behavior under test. Unknown replay events fail the process; `no_seam` and projected observations are never passes. Code can be split into submodules as it grows without changing crate ownership.

## Runtime and effects

Use Tokio's multithread runtime for queue orchestration, HTTP, timers, signal handling and process supervision. A process remains the unit of every CLI call; `queue start --detach` starts a supervised child, not a daemon service. Keep the drain serial even if provider I/O, stdout pumps and process watchers are concurrent. Blocking Git invocations use `spawn_blocking` or `tokio::process::Command` with bounded output. Store snapshots atomically after journal append; fsync the file and parent directory at publication boundaries.

Use `reqwest` with `rustls` and a streaming body; parse SSE incrementally from bytes rather than collecting an unbounded response. Implement the spec's CR/LF framing, 16 MiB cap, first-body-byte, idle and total deadlines, cancellation and partial-stream continuation. Fake HTTP/OAuth endpoints come only from the documented test seams. The wire serializer must write deterministic field order with `input` last and stable nested keys. Capture raw request bytes and headers in fake-provider tests. JSON value maps may be used for semantic records, but a deliberately ordered request struct or serializer is required for the byte-prefix test. Login secrets remain in Kogen's own store and are absent from argv, logs and Git.

Invoke the host `git` executable with explicit argv and private index/worktree configuration. This is preferable to `gitoxide` here because conformance exercises the exact Git object/ref behavior, local bare origins, hooks disabled, signing identity, SHA-256 repositories, checked-out branch warnings and `update-ref` compare-and-swap. Git is already a suite prerequisite; a second implementation of those edge cases would increase risk. Pass commit messages by stdin or a private file, never argv. Disable hooks, filters, fsmonitor and workspace excludes for Kogen-controlled operations. A landing commit has one expected base parent, contains the approved Intent and candidate test, and is published only by a fast-forward ref CAS. Preserve a landing record and incoming ref before CAS; after a lost CAS, rebuild/re-gate on the new tip. After CAS, recovery must identify a reachable landing as landed even if cleanup or the process failed.

For child custody, run every child in its own process group/session; stream to a private log, enforce wall deadlines regardless of output, TERM then KILL the group, and reap grandchildren. A parent-death watcher must cover SIGKILL of Kogen. Pass model shell commands through a mode-0600 script path under the run dir, keeping content and secrets out of argv (4 KiB element limit). Implement macOS and Linux confinement behind one interface, with the specified unconfined warning and checkout/origin integrity check when confinement is unavailable.

## Storage and source bytes

In the checkout, the draft is `.kogen/intents/<slug>/intent.md` and the acceptance source is `.kogen/acceptance/<slug><ext>`. Approval snapshots both exact byte sequences under `refs/kogen/intents/<slug>` with `approval.json`, optional `ledger.json`, and a protected manifest. The approval digest is SHA-256 over Intent bytes, one NUL, then test bytes. The separate `intent_sha256` covers Intent bytes alone. A mismatch runs no checks; a change before approval CAS writes no ref.

The origin holds `refs/kogen/claim`, `refs/kogen/incoming/<run_id>`, candidate and parked refs, and the base head as specified in §2.5. The base head moves only after verified tree preparation and ref CAS. The run's `landing` record is durable before that move.

Machine state is under `$HOME/.kogen`: `config.yaml`, `accounts.yaml`, `profiles.json`, `host.json`, `credentials/`, `locks/`, and `workspaces/<key>/`. The key is the canonical checkout basename (sanitized, at most 40 characters) plus the first 10 hex digits of its SHA-256 path digest. Each workspace root contains `runs/<run_id>/run.json`, `events.jsonl`, `transcript.jsonl`, `logs/`, `ledger.jsonl`, `candidate.diff`, `tmp/` and `mise-*`; rung clones, `setup-cache/`, `approval-cache/`, `queue.pid`, `queue.stop`, `queue.log` sit beside `runs/`. Files containing credentials or candidate content use private permissions. JSON readers ignore unknown fields; writes are compact UTF-8 with durable atomic replacement where the spec requires it. `status` derives from refs, reachable base commits and runs; it is not a mutable status flag.

## Error contract

One typed error carries `class`, snake-case `reason`, detail, and exit. The CLI renderer owns newline and stream placement: normal results and error lines on stdout; only specified progress, deprecation and landing/sandbox warnings on stderr. Exit mapping: 0 done, 1 negative result, 2 usage/caller correction, 3 environment, 4 provider, 5 approval card/decision, 70 internal bug, 130 SIGINT, 143 SIGTERM. Usage errors render the exact meant help page. `--json` does not convert errors to JSON. Provider failures that stop the drain retain the Intent queued; ordinary candidate failure ends that Build and permits subsequent queued work when specified. No Rust debug or panic formatting reaches the public error line.

## Prompt caching design and provenance

The installed npm `@openai/codex` source at `~/.local/share/mise/installs/node/24.21.0/lib/node_modules/@openai/codex/bin/codex.js` is a launcher for a native binary; it exposes no request-construction source. The local readable Codex source snapshot at `../benchmark-night-2026-10-01/harness-mining/src/codex/codex-rs/core/src/client.rs` (around `prompt_cache_key` and `responses_session_id`) keeps cache affinity separate from actual thread identity. Pi's `../pi-mono/packages/ai/src/providers/openai-codex-responses.ts` constructs `prompt_cache_key` and the `session_id` header from its session id; `openai-responses.ts` makes caching conditional on cache retention. These are source observations, not evidence that a Kogen request will hit cache.

Kogen follows the v1.2 contract: one opaque Build-level cache key survives stage/rung/attempt/model transitions; `session-id` matches it; `thread-id` and journal `conversation_id` identify a distinct stage/attempt/rung/epoch thread. Static instructions, tool schemas and controls precede the append-only `input` field. Same-model turn N's body, minus final `]}`, must prefix turn N+1; identical retries send identical bytes. Do not send `previous_response_id` or store remote responses. Record `input = input_tokens - cached_tokens` only when both are valid, preserve null otherwise, and derive the rate from measured cached and uncached input. Fake-provider tests establish wire behavior. A credential-safe live three-turn smoke must separately show **more than 95% cached input on every third-and-later turn**, reporting numerator, denominator and missing warm records; it is a release gate, not a skeleton claim.

## Verification and priority

`make check` runs workspace rustfmt check, clippy with warnings denied, and unit tests. Unit tests cover pure parsers, hashes, ordering, SSE frames, request bytes and state transitions. The read-only `../kogen-conformance` branch `v1.2` drives real `kogen` via `bin/kogen-conformance`; run named cases for each work package and then the full applicable profiles. It contains 244 frozen v1.1 cases and six named v1.2 cases; old cases can conflict with the fixed v1.2 surface, so report those conflicts explicitly and never edit the suite to make a result green. `tmp-proxy-debug` is not a release case. A future suite version and the spec's P1–P13 cases remain separate evidence where no black-box file exists.

For each guaranteed Quint slice, run all checked-in hand scenarios and generated traces (`500` traces × `25` steps for each seed `17`, `23`, `41`) with exact full observations through `kogen-xspec`. Record both binary SHA and first divergence. The `gate` and `orchestration` slices contain likely/experimental rules; their full traces are diagnostic until a versioned guaranteed kernel exists in the spec repository. The guaranteed green gate is proven by black-box cases and unit tests meanwhile. Historical `resilience` and prototype landing are not release gates. Guaranteed work precedes likely work as listed in `docs/work/QUEUE.txt`.

Pin Rust `1.97.1` with the minimal profile and rustfmt/clippy components in `rust-toolchain.toml`; Cargo edition 2024 and resolver 3. Commit `Cargo.lock` with implementation dependencies. Keep this repository CI-free; local `make check` is the required baseline.
