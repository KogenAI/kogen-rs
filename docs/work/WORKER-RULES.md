# Worker rules

Read `ARCHITECTURE.md`, `../../../kogen-spec/CLI-RULE.txt`, the cited spec sections, and the package before editing. The fixed public CLI has no extra commands or flags; `kogen-xspec` is private and separate. Classification in `../../../kogen-spec/quint/CLASSIFICATION.md` determines release priority. The Elixir tree is reference material, never authority.

Own only the files named by the package unless an interface change is coordinated with the adjacent owner. Put behavior in `kogen-core`; `kogen` renders the public contract and `kogen-xspec` decodes/injects/observes production transitions. Do not duplicate policy in the replay adapter. Keep source files at or below 400 lines, split modules when approaching that limit; generated and embedded help data are exempt. Keep functions focused and errors typed. No `unsafe` in the workspace without an architecture amendment and a clear need.

Definition of done for each package: its specified behavior and named compatible conformance case IDs pass; `make check` is green; its listed guaranteed Quint slices pass **all** hand scenarios plus generated `500 × 25` traces for **each** seed 17, 23 and 41 through `kogen-xspec`, with exact full observations. A package marked with no slice has no trace requirement. Whole `gate`, `orchestration`, `accounts`, and `setup-cache` replays remain diagnostic under their current classification. A v1.1 case that asserts a superseded v1.2 rule is still run and reported with its exact failed assertion, alongside the matching v1.2 case; it is never changed or counted as a pass. If a named case requires another package, merge that dependency before marking the package done. Run with temporary HOME and fake endpoints; no installed Codex/pi process or real credentials in tests.

Do not edit, skip, relax or replace conformance cases, golden help, or Quint expectations to get green. Never count `--project` projection, `no_seam`, skipped cases or unimplemented cases as a pass. For a genuine spec/case conflict, capture the failing ID and observed bytes, note the v1.1/v1.2 boundary, and request a versioned correction in the source repository. Do not make an unsupported release claim. The supplied conformance checkout is read-only for this work.

Record in the package or commit note: source SHA, binary SHA, exact case command and pass/fail IDs, hand scenario count, trace seeds/steps and first divergence, if any. Keep commits short, factual, with normal git identity and no trailers. No CI configuration. `make check` remains the local gate.
